The transaction lock time is now determined following BIP 370 (and Bitcoin Core's reference implementation) for inputs that specify both `required_time_lock_time` and `required_height_lock_time`: such an input supports both lock time types, so the transaction's lock time is determined normally (preferring the height lock time) instead of being reported as an incompatibility. `TransactionExtractor::extract` no longer fails with `ExtractError::IncompatibleLockTimes` for PCZTs whose inputs specify both lock time fields.

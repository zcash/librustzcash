The transaction builder now builds Sapling PCZTs during the ZIP 212 grace period (the first 32256 blocks after Canopy activation). A builder always creates notes with the post-ZIP 212 plaintext lead byte, which recipients accept from Canopy activation onward, so the only observable change is that `Builder::build_for_pczt` no longer fails with `Error::SaplingBuild(sapling::builder::Error::PcztRequiresZip212)` for target heights inside the grace period. Previously such networks (for example, regtest-style networks that activate every upgrade at height 1) could not build Sapling PCZTs until 32256 blocks had been mined.

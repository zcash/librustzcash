With `transparent-inputs`, when the wallet detects that an account received
or spent transparent funds in a block below the account's birthday, it now
lowers the birthday to that block's height.
`WalletRead::suggest_scan_ranges` then returns the blocks from the new
birthday (or Sapling activation, if later) up to the previous birthday,
including blocks that were already scanned. The migration that checks stored
transactions can lower a birthday in this way.

`WalletDb`'s implementations of `WalletRead::get_transaction` and
`LowLevelWalletRead::get_unknown_fee_spenders_of` now return an unmined
transaction exactly as stored when its stored expiry height is missing or
zero. Previously they rebuilt such a transaction from its parts, which
dropped the Ironwood bundle of a v6 transaction and replaced the consensus
branch ID that a v5 or later transaction commits to. The returned
transaction then had a different txid, and `WalletWrite::store_decrypted_tx`
could record a wrong fee for it.
